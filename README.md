# Гант — планировщик задач (одностраничное приложение)

`dist/Gantt.html` — **готовое приложение одним файлом**. Открывается двойным кликом
(file://), работает офлайн: SheetJS, стили и весь код вшиты внутрь. Загрузка задач —
через кнопку «Загрузить xlsx» или перетаскиванием файла на страницу.

## Файлы

- `dist/Gantt.html` — планировщик.
- `dist/Конвертер.html` — конвертер РКК.xlsx → Шаблон.xlsx (ссылка «Конвертер РКК» в шапке Ганта).

## Конвертер РКК → Шаблон

Читает лист «26 4к» файла РКК.xlsx: названия задач — колонка H, строки 60–97;
приоритет — колонка A; часы — колонки AG–AY (фамилии в строке 48); стек
исполнителя — таблица H/I, строки 4–36 (значение вида «Python / meth»);
**готовность ТТ — колонка E**: задача не может начаться раньше этой даты, при
пустой или «не готово» начало сдвигается на неделю вправо от сегодняшнего дня
(такие строки перечисляются в отчёте). Даты пишутся в колонку «Не раньше»
шаблона — Гант читает её как жёсткое ограничение.

Маппинг стеков: C# / .Net / net / Дотнет → Дотнет, TS / Front / front / Фронт →
Фронт, Python / Питон → Питон, C++ → C++. Один и тот же стек, записанный
синонимами (`C# / .Net`), считается одним стеком, а не «несколькими навыками». Роли вне
этих четырёх (meth, Тест, DevOps, Сист. анализ, Дизайн, ВП, МП, Архитектор)
попадают только в отчёт конвертера. Строки без часов переносятся — Гант покажет
их с пометкой «нет фаз»; разделители без «ТТ» в названии пропускаются.

Если один стек в задаче делают несколько человек, в шаблоне остаётся главный
блок (первый по порядку колонок), а остальные фазы пишутся в дополнительные
тройки колонок **Стек (доп.) | Часы (доп.) | Исполнитель (доп.)** начиная с
колонки R. Гант читает эти тройки как обычные последовательные фазы того же
стека — они рисуются тем же цветом и подписаны исполнителем.

Мультистековый исполнитель (например, «C# / Python») не забирает стек, который
может делать моно-исполнитель: если на задаче есть человек только с C#, то
мультистековый уходит на Python. Если свободных стеков нет, берётся первый из
его списка — выбор и причина видны в отчёте конвертера.

## Формат входного файла

Шаблон `Шаблон.xlsx`, первый лист:

| Колонка | Поле |
|---|---|
| A, B | Номер, Приоритет |
| C | Название |
| D | Общая длительность, дн (план с учётом простоев) |
| E, F | Начало / окончание базовое |
| G, H | Начало / окончание фактическое |
| I | Оценка SP |
| J–Q | 4 стека: C++ / Питон / Дотнет / Фронт — пары «часы, исполнитель» |
| R | **«Не раньше»** — дата, раньше которой задача не начинается (жёсткое ограничение) |
| S и далее | доп. фазы тройками: стек / часы / исполнитель |

Фаза берётся в работу только если у неё есть часы > 0 и исполнитель; иначе строка
получает предупреждение и на графике помечается как «нет фаз».

## Модель планирования

- Рабочий календарь: пн–пт, 8 часов в день, праздники РФ 2026–2027 (список
  **черновой**, редактируется в панели «Производственный календарь»; правки
  сохраняются в localStorage).
- Часы фазы переводятся в рабочие дни: `дней = часы / 8`. Выходные и праздники
  время не потребляют.
- Фазы одной задачи идут **последовательно** в заданном порядке
  (по умолчанию C++ → Питон → Дотнет → Фронт). Порядок меняется в панели
  «Задача» (кнопки ↑/↓ у выбранной строки).
- **Исключение: C++ и Питон одной задачи идут параллельно, если это разные
  исполнители** — два независимых бэкенд-куска. Дотнет ждёт окончания обоих.
  Если исполнитель один, C++ и Питон остаются последовательными. Параллельные
  фазы рисуются в отдельных дорожках внутри строки.
- **Даты из файла — это ограничения.** Задача не начинается раньше самой
  поздней из дат: «Не раньше» (готовность ТТ), базового начала, фактического
  начала (факт важнее всего — уже начатую задачу не сдвинуть). Если задано
  только базовое окончание, начало отсчитывается назад на сумму часов фаз.
  Галочка «Не раньше плана» (включена по умолчанию) отключает базовое
  начало/окончание и возвращает режим «как можно раньше»; готовность ТТ
  продолжает действовать.
  Занятость исполнителей только сдвигает фазы вправо — это и есть «простой»,
  который заложен в колонке D. Время ожидания видно в подсказке фазы.
- **Исполнитель ведёт не более 2 задач одновременно, и две задачи могут
  пересекаться только если их фазы у этого исполнителя различаются в 3 раза и
  более** (крупный блок и мелкий могут идти параллельно, два сопоставимых —
  нет). Третья задача ждёт освобождения. Проверяется на каждом прогоне тестами
  (в т.ч. на стресс-наборе из 12 задач).
- **«Не раньше»** (колонка R): жёсткое ограничение начала — задача не стартует
  раньше даты, даже если исполнители свободны. Фактическое начало (G) важнее
  ограничения: уже начатая задача не сдвигается. Ограничение отрисовано
  пунктирным маркером. Конвертер РКК заполняет его из колонки E «Готовность ТТ»,
  а при пустой (или «не готово») — ставит сегодня + 7 дней.
- **Отсутствия исполнителей** (отпуск/болезнь): панель в сайдбаре, у каждого
  исполнителя может быть несколько диапазонов. Фаза встаёт на паузу на
  пропущенные рабочие дни и заканчивается позже; рабочие часы фазы сохраняются.
- **Нарушение приоритета**: если задача с более низким приоритетом стартует
  раньше более приоритетной (обычно из-за занятости исполнителей или
  зафиксированного фактического начала), выводится предупреждение.
- Номера задач могут повторяться в файле — строки разводятся по индексу,
  выбор и инспектор работают с конкретной строкой.
- Один стек в задаче может встречаться несколько раз (несколько исполнителей):
  фазы идут подряд, тем же цветом, с подписью исполнителя.
- Если в Гант загрузить файл с чужими заголовками (например, РКК.xlsx напрямую),
  появляется предупреждение со ссылкой на конвертер.
- Завершённая задача (заполнена колонка H) не планируется.
- Порядок разбора задач для планировщика: приоритет, затем номер.
- Предупреждения: перерасход относительно колонки D, выход за базовый план,
  фаза без исполнителя, строка без фаз, превышение лимита 2 задач.

## Интерфейс: соответствие эвристикам Нильсена

Фильтр над диаграммой: по исполнителю (список берётся из файла) и по части
названия, фильтры складываются. Это только вид — расписание не пересчитывается,
шкала подстраивается под отфильтрованные задачи. Клик по предупреждению снимает
фильтр, чтобы показать нужную задачу.

| Эвристика | Как сделано |
|---|---|
| Видимость состояния | имя загруженного файла и окно расчёта в строке состояния; счётчик «N ошибок · N предупреждений · N замечаний» в панели «Проверка» |
| Связь с реальностью | «Приоритет 1 (высший)» в карточке задачи; даты в формате ДД.ММ.ГГГГ |
| Свобода действий | карточку задачи закрывает × или Esc; панели сворачиваются, состояние запоминается |
| Консистентность | одинаковые кнопки/поля во всех панелях; кнопка темы подписана, у иконочных кнопок есть aria-label |
| Предотвращение ошибок | формы праздников и отпусков проверяют формат, повторы и обратные диапазоны и пишут причину под формой |
| Узнавание | предупреждения разбиты на уровни (⛔ Ошибки / ⚠ Предупреждения / ⓘ Замечания) с иконкой, подписью и счётчиком; длинные группы свёрнуты в три строки с кнопкой «Показать все» |
| Гибкость | фильтр по исполнителю и части названия (только вид, расписание не пересчитывается); горячие клавиши: Esc, +/−, T, / — поиск, ? — справка |
| Минимализм | пять панелей стали сворачиваемыми блоками, длинные списки предупреждений схлопнуты |
| Диагностика | клик по предупреждению подсвечивает нужную задачу и прокручивает к ней; задача помечена «нет фаз» прямо в строке |
| Помощь | кнопка «?» — справка с правилами модели: фазы, параллельный C++/Питон, лимит 2 задачи, правило 3×, отпуска, границы дат, приоритет, горячие клавиши |

## Разработка и тесты

```bash
npm install          # зависимости
npm run fixtures     # сгенерировать тестовые xlsx (tests/fixtures)
npm run build        # собрать dist/Gantt.html из src/
npm test             # Playwright E2E, 143 теста
npm run test:headed  # то же с открытым браузером
```

Тесты прогоняются против собранного `dist/Gantt.html` по `file://`, загружают
фикстуры через реальный `input[type=file]` и проверяют как DOM, так и внутреннее
состояние приложения (`window.__gantt`). Отдельный тест измеряет покрытие кода
приложения через V8 coverage Chromium — сейчас **93.6%** (порог в тесте 85 %).
Отдельный набор `tests/geometry.spec.mjs` сверяет пиксельные позиции полос с
расчётными датами — он ловит ошибки раскладки, при которых фазы визуально
«разъезжаются», хотя расписание корректно. `tests/converter.spec.mjs` проверяет
конвертер (включая выгрузку файла и загрузку результата в Гант) и измеряет его
покрытие — сейчас 96.2%.

Структура: `src/` — исходники (calendar, parse, schedule, render, app),
`src/build.mjs` — сборка одного файла, `tests/` — фикстуры и спеки,
`vendor/xlsx.full.min.js` — SheetJS 0.18.5 (в npm-версии есть известные
CVE по prototype pollution/ReDoS; для локального офлайн-приложения риск
ограничен разбором собственных файлов, но при желании замените на сборку
с cdn.sheetjs.com).
